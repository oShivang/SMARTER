# `evaluation/python_executor.py` — Python Execution Environment Sandbox

## What Is This File?

This file provides a execution environment (sandbox) to execute python code dynamically generated by LLMs (e.g., in PAL/PoT or Tool-Integrated Reasoning setups). It isolates execution inside a separate process pool using pebble/multiprocessing and applies strict timeout filters.

---

## Input Format

- **Code Block / String**: Individual string representation of a Python script.
- **`batch_apply(code_list)`**: Takes a list of Python scripts/functions (`list[str]`) to evaluate in parallel.

---

## Output Format

Returns a list of tuples: `list[tuple[str, str]]`
- **`result_str`**: The return value or stdout of the python execution (cast to string, or empty if an error occurred).
- **`report_str`**: The execution status or traceback reports (e.g., `"Done"`, `"Timeout Error"`, or exception messages).

---

## What It Does

1. **In-Memory Sandboxing**: Uses Python's `exec` and `eval` inside isolated namespace dictionaries to simulate runtime environments (`GenericRuntime`).
2. **Context Injection**: Exposes custom symbols, standard utility libraries (e.g. `datetime`, `dateutil`, `sympy`), or special variables to target runtimes (like `DateRuntime` and `ColorObjectRuntime`).
3. **Robust Parallel Execution**: Runs code blocks concurrently inside a Process Pool (`ProcessPool` or `multiprocessing.Pool`) with pebbles and signals to prevent hangs, infinite loops, and OOMs.

---

## How It Does It (In Detail)

### 1. The Runtime Classes (`GenericRuntime`, `DateRuntime`, `ColorObjectRuntime`)

- **`GenericRuntime`**: Holds global and local namespaces. It runs code sequentially inside a context where stdout is redirected via `io.StringIO`.
- **Specialized Runtimes**: Extend `GenericRuntime` to inject library modules automatically:
  - `DateRuntime`: Pre-injects `datetime`, `timedelta`, `relativedelta`, and sympy helper namespaces.
  - `ColorObjectRuntime`: Injects color-object mapping lists.

### 2. Execution Coordinator (`PythonExecutor`)

- **Instantiation**: Configured via flags (e.g., `get_answer_expr` to evaluate a specific function call like `solution()`, or `get_answer_from_stdout` to extract printed output).
- **Process Isolation**: The actual execution of code occurs in `PythonExecutor.execute`. It redirects `sys.stdout` and `sys.stderr`, runs `exec` over the code, and evaluates the target output.
- **Serialization Guard**: The result object is pickled/serialized back across the process boundaries. If a result is unpicklable, the script returns its string representation.
- **Process Pool Pool Wrapper (`batch_apply`)**: Uses `pebble.ProcessPool` to spawn processes for each code snippet. It limits the time budget of each process (default 10 seconds). If a process exceeds its budget, it is terminated, returning `("Timeout Error", "Timeout Error")`.
